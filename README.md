# Сходка

Мини-приложение и чат-бот для MAX, которые помогают людям 16+ находить компанию для любительской физической активности в Москве.

## Основной сценарий

1. Пользователь открывает каталог спортивных активностей.
2. Выбирает подходящую сходку и отправляет заявку.
3. Организатор подтверждает или отклоняет заявку.
4. После подтверждения активность появляется в разделе «Мои сходки».
5. Бот уведомляет пользователя об изменении статуса и напоминает о встрече.

## Статус MVP

Работают каталог, фильтры, создание активности, заявки, подтверждение организатором, раздел «Мои сходки» и отмена активности. До подключения MAX приложение использует демонстрационного пользователя. Формат MAX API будет добавлен только по актуальной документации платформы.

## Технологии

- React, TypeScript, Vite
- Node.js, Express, TypeScript
- JSON-хранилище для воспроизводимой демонстрации MVP
- Docker и Docker Compose

## Локальный запуск

```bash
cp .env.example .env
npm install
npm run dev
```

Frontend: http://localhost:5173  
API: http://localhost:3000  
Проверка API: http://localhost:3000/health

## Запуск через Docker

```bash
cp .env.example .env
docker compose up --build
```

Frontend: http://localhost:8080  
API: http://localhost:3000

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | Порт backend |
| `WEB_ORIGIN` | Разрешённый origin frontend |
| `DATA_FILE` | Путь к файлу данных |
| `MAX_BOT_TOKEN` | Токен бота MAX; хранится только в `.env` или секретах хостинга |
| `MAX_BOT_API_URL` | Актуальный базовый адрес API MAX |
| `MINI_APP_URL` | Публичный HTTPS-адрес мини-приложения |

## Демонстрационные пользователи

- `user-1` — Ира, обычный участник
- `user-2` — Саша, организатор тестовых активностей

В текущем frontend выбран `user-1`. После подключения MAX идентификатор должен поступать из проверенных данных платформы, а не из произвольного параметра клиента.

## Известные ограничения

- Используются подготовленные тестовые данные; реальная интеграция с каталогами событий отсутствует.
- MAX API пока не подключён: нужен токен и актуальная документация организаторов.
- Данные хранятся в JSON-файле и рассчитаны на один экземпляр сервера MVP.
- Точный адрес скрыт в каталоге и возвращается участнику только после подтверждения заявки.
- Проверка возраста и полноценная модерация не реализованы.

## Порядок проверки

1. Открыть frontend.
2. Выбрать карточку активности и нажать «Подать заявку».
3. Перейти в «Мои сходки» и убедиться, что заявка отображается со статусом ожидания.
4. Создать новую активность через форму.
5. Для проверки роли организатора выполнить запрос списка заявок для `user-2` через API или временно заменить демонстрационного пользователя во frontend.

## Безопасность

- Секреты не хранятся в репозитории.
- Точный адрес не показывается неподтверждённым участникам.
- В production необходимо валидировать данные запуска мини-приложения MAX на backend.
- Перед пилотом требуется проверить правила платформы и применимые требования к аудитории 16+.
